# Troubleshooting

## Camera or microphone does not start

Devices start off intentionally. Use the preview/device control to request access and check the browser's site permission panel. Close another application holding the device, select a working device in browser/OS settings, and retry. A denial is not fixed by repeatedly joining a room.

Remote devices require HTTPS. `http://localhost:3000` works as a local secure-context exception, while a plain HTTP LAN address usually cannot use camera/microphone. Screen sharing also depends on browser/OS support and needs an explicit picker selection.

## A second participant cannot join

Use a distinct display name; a duplicate live name is rejected rather than replacing the first connection. Names must be 1–40 characters after trimming. Room IDs must be 1–100 letters, digits, underscores, or hyphens. Use a link generated by your own instance, not a room link on a different host.

If a tab disconnected, close it cleanly and rejoin. An app restart clears room membership. There is no persisted room to recover or account history to restore.

## The page loads but the call does not connect

1. Check browser permissions and that both participants actually joined the same instance/room.
2. Inspect the browser's Network panel: `/_ws` must upgrade and remain connected. A reverse proxy must forward WebSocket upgrade traffic, not just serve HTML. The supplied Caddy configuration does this.
3. Check `POST /api/getIceUrls` status without sharing its authorization header or response credentials. Ensure the runtime has both TURN values, not just a build-time `.env`.
4. Try two devices on different networks. Same-device/same-network success does not prove TURN fallback works, and a restrictive corporate network can still block media.
5. Check host logs and Cloudflare TURN status/usage. Do not print credentials into logs for diagnosis.

The server does not relay media itself. Increasing the Node port's firewall exposure or adding an app data volume does not fix blocked WebRTC connectivity.

## ICE endpoint errors

| Status | Meaning / next action |
| --- | --- |
| 401 | No valid live capability for this room, session expired, or it was revoked. Rejoin through the normal UI. A direct unauthenticated API request is expected to fail. |
| 429 | Session request budget, provider cooldown, or process-wide provider issuance budget reached. Respect the returned retry delay; stop repeated joins/refreshes and inspect usage. |
| 502 | Cloudflare credential issuance failed or returned an unusable response. Check provider status and server-side key/token configuration. |
| 503 | TURN settings are missing. Set both server-only variables in the actual runtime environment and recreate/restart appropriately. |

Capabilities last one hour. Long-call automatic renewal is not supported. A server restart also invalidates admission; refresh/rejoin instead of reusing a previous capability.

## Caddy cannot issue a certificate

Verify public DNS points to the host, both A and AAAA records are correct, TCP 80/443 reach Caddy, and no existing service occupies those ports. Review Caddy's logs:

```sh
docker compose --env-file "$HOME/.config/litsi/deploy.env" -f deploy/compose.yaml logs --tail=100 caddy
```

Do not repeatedly delete Caddy volumes: doing so discards certificate state and can contribute to certificate-authority rate limiting. See [Caddy's automatic HTTPS guidance](https://caddyserver.com/docs/automatic-https).

## Calls drop on deploy, restart, or scale changes

This is an in-memory single-process server. Deploys and restarts clear live rooms; ask participants to rejoin. Keep exactly one process/machine, including `fly scale count 1` on Fly. Multiple workers or replicas are not a supported availability strategy.

## Analytics still seems enabled after editing env

An empty `NUXT_PUBLIC_TELEMETRYDECK_APP_ID` disables the client. Check the actual container/process environment and recreate it: Compose `restart` does not update environment variables. Another tab may still be running previously loaded code; reload after applying the change. Do not provide an analytics ID merely to eliminate a setup warning.

## Documentation links or assets fail on Pages

The build defaults to `/` for the `litsi.nirjan.dev` custom domain; use `DOCS_BASE=/litsi/` only for the `nirjan-dev.github.io/litsi/` project site. Rebuild after changing it; runtime env changes cannot rewrite a static bundle. Enable GitHub Actions as the Pages source and inspect the separate **Docs** workflow, not the Fly deploy logs.

## Reporting an issue

[Open an issue on GitHub](https://github.com/nirjan-dev/litsi/issues) with browser/OS, steps, whether devices use different networks, relevant HTTP status codes, and sanitized error text. Remove names, room links, capability headers, TURN responses/tokens, and private chat from logs or screenshots. Do not claim a test was performed if you only inspected the code.
